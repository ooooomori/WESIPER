# 선수 검색 정렬과 성능

검색은 현재 이름 일치, 전체 이름, 이전 이름, 별명 순서를 유지한다. 현재 이름 안에서는 완전 일치 → 접두 일치 → 부분 일치를 우선한다. 같은 일치도 안에서는 통산 1군 정규시즌 경기 수 내림차순으로 정렬한다. 1군 정규시즌 경기 수가 0인 선수끼리는 2군 경기 수 내림차순으로 정렬한다. 그 외 동률에는 이름·이미지 연도·선수 ID의 기존 순서를 유지한다. 화면의 현역·은퇴 그룹은 유지한다.

`player-search-stats.php`는 검색에 걸린 선수만 일괄 집계한다. 2001년 이후의 1군 정규시즌 범위 안에서 경기 ID 앞 13자리를 중복 제거해 여러 타석과 투타 겸업을 한 경기로 센다. 1982~2000년은 공식 정규시즌 연간 total 행을 사용하며, 타격·투구 중 큰 경기 수를 연도별로 선택한다. 퓨처스·시범경기·포스트시즌·이적 팀별 중복 행은 경기 수에서 제외한다.

마지막 기록 연도는 기존대로 모든 리그의 타격·투구·과거 연간 기록을 고려한다. 은퇴 선수의 이전 소속팀은 1군·2군 타격·투구 기록 중 팀이 있는 가장 최근 경기 기준이며, 저장된 프로필 팀보다 우선한다. 경기 기록에서 팀을 찾지 못하면 저장된 팀을 사용한다. 리그별 인덱스 범위 조회를 일괄 처리해 조회 횟수를 줄인다. API는 `FirstTeamGames`를 추가로 제공한다.

2군 경기 수도 경기 ID 앞 13자를 기준으로 타석·투타 중복을 제거한다. 1군 정규시즌 경기 수가 0인 검색 선수만 추가 집계하므로 1군 출전 선수의 2군 기록은 읽지 않는다. 정렬용 집계는 내부 데이터로 사용한다.

경기 수·마지막 연도 캐시는 DB와 정규시즌 범위별로 분리하고 최대 5분 유지한다. 2군 정렬 도입 시 캐시 파일 버전을 v2로 변경했다. 크롤러의 `WESIPER_CANDLE_REVISION_FILE`(기본 `/tmp/wesiper-candle-data-revision`)이 변경되면 즉시 무효화한다. 새 검색 선수를 캐시에 추가해도 만료 시각은 연장하지 않는다. 파일 생성에 실패하면 직접 조회한다.

## 인덱스와 검증

2026-10-02 공유 DB의 두 경기 기록 테이블에 `idx_search_league_player_game (league_level,player_id,game_date,game_id)`를 추가했다. 기존 인덱스와 선수·경기 데이터는 유지한다. 다른 DB에 적용하려면 `deploy/add-player-search-indexes.php --apply <비공개 DB 설정 경로>`를 실행한다. 스크립트는 기존 인덱스를 확인하고 온라인 DDL만 사용한다.

로컬 DB 터널에서 `김민` 67명 검색을 측정했을 때 캐시 없는 함수 호출은 초기 10.6초에서 약 1.5초로 줄었다. 캐시가 있는 실제 Vite API 요청(`127.0.0.1:5173`)은 `김민` 약 0.57~0.65초, `이승엽` 약 0.46초였다. 프런트엔드 입력 대기는 500ms에서 250ms로 줄였다. 응답 시간은 DB 부하·캐시·네트워크에 따라 달라진다.

`deploy/test-player-search.php`에서 이름 우선순위, 경기 수 정렬, 타석·투타 중복, 과거 total 행, 제외 시즌, 마지막 기록 연도, 이전 팀 일괄 조회 및 기존 별명·리터럴 검색을 검증했다. `backend/tests/player_search_last_year_test.php`, PHP 문법 검사와 프런트엔드 빌드도 통과했다. 실제 데이터 측정은 `deploy/benchmark-player-search.php <DB 설정 경로> [--uncached]`로 재현할 수 있다.
