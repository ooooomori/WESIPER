# KBO CANDLE 다음 타격 경기 예측

## 지원 범위

- **2026년 / 정규시즌 / 전체 시즌** 조회에만 예측 카드를 표시한다.
- 전체 시즌 검색도 시작일/종료일을 전송하므로 `date_preset=whole`과 기존 일정표의 전체 범위를 함께 검사한다. 빈 날짜 쌍도 전체 조회로 허용한다.
- 다음 **출전하는 같은 시즌 경기** 이후의 시즌 누적 AVG/OBP/SLG/OPS 상승·유지·하락과 한 경기 1안타 이상·1홈런 이상 확률을 예측한다. 선발 출장은 가정하지 않는다. 결장 확률이나 팀의 다음 경기 일정을 예측하지 않는다.
- 현재 DB만 읽는다. 모델/백테스트에는 KBO·네이버 요청 코드가 없다. 기존 일일 수집 외에 새 데이터 수집은 추가하지 않는다.
- 타방은 PA에 포함, AB/OBP 분모에는 제외한다. 희선 계열은 사용자 확정 규칙에 따라 무안타 AB다. 빈 도루 전용 행은 PA에서 제외한다.

## 구성

| 파일 | 역할 |
|---|---|
| `crawler/prediction_model.py` | 결과 정규화, 경기 집계, 확률 분포, 정수 기반 방향 판정 |
| `crawler/prediction_data.py` | 기존 MySQL/오프라인 스냅샷 읽기, 기존 PHP 일정 재사용 |
| `crawler/predict_next_game.py` | 야간 추론, 명시적 테이블 초기화, 트랜잭션 저장 |
| `crawler/backtest_predictions.py` | 시간순 비교, 확률 점수, calibration 및 날짜별 bootstrap |
| `backend/api/kbocandle/predictions.php` | 대상 조회 판정, 저장된 예측 조회, 오래된 결과 차단 |
| `frontend/src/pages/Kbocandle/PredictionCard.jsx` | 기존 기간 성적 아래 라이트/다크 카드 |

신규 집계 테이블 `kbo_player_game_stats`는 2026 정규시즌 선수×경기를 저장한다. `event_counts`에는 1B/2B/3B/HR/SH/CI 등의 구분을 유지한다. 학습 시에는 2018년 이후 과거 원천 기록을 직접 집계한다.

`kbo_player_predictions`는 선수/연도/기준일/모델 버전/데이터 해시별 예측을 보관한다. 같은 스냅샷의 재실행은 중복을 만들지 않는다. 원천 기록은 수정하지 않으며 이전 스냅샷의 예측은 보존한다. 파생 집계 교체와 예측 저장은 한 트랜잭션으로 처리한다.

## 모델 v2

- 학습 대상: 2018년 이후 정규시즌만. 시즌 경계는 `common.php`의 `getKBOSchedule()`과 동일하다.
- 사건: 무안타 AB, BB, HBP, 1B, 2B, 3B, HR, SF, SH, 타방.
- 타격 확률: 선수별 과거 사건 횟수를 365일 반감기로 가중하고, 그 시점까지의 리그 사건 분포 100타석으로 보정한다.
- 다음 경기 PA: 선수의 최근 20개 기록된 출전의 PA 빈도 + 과거 리그 경기 PA 분포 5경기분. 교체 출전과 원천 행이 있는 PA=0 출전을 포함한다. 수비만 하고 원천 행이 없는 출전은 현재 DB에서 알 수 없다.
- 최소 표본: 과거 5경기/20PA 및 현재 시즌 AB>0. 미달이면 확률 대신 상태를 반환한다.
- 한 시뮬레이션의 경기 기록으로 네 지표 방향과 1안타·1홈런 이상 여부를 함께 계산한다. OPS 확률을 OBP/SLG 확률에서 평균내지 않는다.
- up/down/flat은 정수 교차곱으로 판정한다. API의 소수 셋째 자리 값으로 정답을 만들지 않는다.
- 일일 추론은 선수당 100,000회, 검증은 표본당 2,000회. 최대 Monte Carlo 표준오차는 각각 약 0.158%p, 1.118%p다. 95% 오차폭은 표준오차의 약 두 배이며 모델 오차와는 다르다.
- 선수/기준일/모델 버전 seed로 동일 실행을 재현한다. 모수와 분류/학습 규칙을 변경하면 `VERSION` 및 PHP 조회 버전도 변경해야 한다.
- v2는 posterior 평균을 사용하는 보정 빈도 모델이다. 타석 간 독립성, PA와 타격 결과의 조건부 독립성을 근사하며 투수/라인업/구장 효과는 사용하지 않는다.

## 시간순 백테스트

2026-09-16까지의 기존 DB 스냅샷으로 실행했다. 원본 행 542,731개를 읽어 정규시즌 선수×경기 145,747개를 집계했다. 선수의 기록된 출전일마다 다음 기록된 출전을 연결하되, 선수/날짜 해시로 약 20%를 결과와 무관하게 선택했다. 2019~2026년 평가용 완료 표본은 24,426개다.

예측일의 모든 경기가 끝난 이후에만 feature를 만든다. 더블헤더는 당일 OHLC 하나로 합치며 목표는 이후 날짜의 첫 기록된 출전이다. 시즌을 넘어 목표를 연결하지 않는다. 학습에는 분할 경계 이전에 **정답 경기까지 끝난** 행만 사용한다.

| 테스트 시즌 | 학습 표본 | 별도 보정 기간 표본 | 테스트 표본 |
|---|---:|---:|---:|
| 2024 | 12,318 (2022년까지) | 3,170 (2023) | 3,114 |
| 2025 | 15,488 (2023년까지) | 3,114 (2024) | 3,083 |
| 2026 | 18,602 (2024년까지) | 3,083 (2025) | 2,741 |

네 지표 평균 Brier score. **낮을수록 좋다.**

| 테스트 시즌 | 과거 상승 빈도 | OHLC-only | 원천 기록 v2 | 원천 기록+확률 보정 | 원천 기록+OHLC |
|---|---:|---:|---:|---:|---:|
| 2024 | 0.24132 | 0.23821 | **0.23581** | 0.23661 | 0.23646 |
| 2025 | 0.24005 | 0.23929 | 0.23653 | 0.23674 | **0.23632** |
| 2026 | 0.23788 | 0.23583 | 0.23563 | **0.23496** | 0.23523 |

OHLC-only는 당일 O/H/L/C, 몸통, 범위, 최근 최대 30일 close 평균/표준편차/변화만 쓰는 ridge logistic baseline이다. 선수 ID·AB·PA는 넣지 않는다. 결합 모델은 이 feature와 원천 모델의 logit을 사용한다. 학습 구간에서만 표준화한다. 확률 보정 비교군은 직전 연도에서만 fit한다. 모든 모델은 같은 예측일·정답·테스트 표본을 사용한다.

**해석:** 원천 기록 v2의 평균 점수는 OHLC-only보다 세 시즌 모두 조금 좋지만, 2026년 paired 날짜 bootstrap 차이 구간은 0을 포함한다. 보정 모델이나 OHLC 결합도 일관되게 우월하지 않아 서비스 모델은 설명 가능한 원천 기록 v2를 BETA로 유지한다. 2026은 부분 시즌이며 이 결과를 본 후의 추가 모델 선택에는 새로운 검증 기간이 필요하다.

2026년 원천 기록 v2의 지표별 결과:

| 지표 | Brier | Log loss | 방향 정확도 | 10구간 ECE |
|---|---:|---:|---:|---:|
| AVG | 0.2378 | 0.6679 | 59.98% | 2.72%p |
| OBP | 0.2424 | 0.6774 | 57.17% | 2.43%p |
| SLG | 0.2237 | 0.6387 | 65.01% | 2.62%p |
| OPS | 0.2386 | 0.6695 | 59.14% | 2.71%p |

Calibration 예: 2026 AVG 예측 30~40% 구간은 770표본, 평균 예측 36.3%, 실제 상승 36.4%였다. 반면 60~70% 구간은 76표본, 평균 예측 63.3%, 실제 상승 51.3%여서 높은 확률에서 과대추정 경향이 있다. 따라서 BETA 숫자를 검증된 정확한 확률로 해석하면 안 된다.

안타·홈런은 다음 출전에서 1개 이상 기록했는지를 별도 정답으로 검증했다. 2026년 Brier는 원천 기록 모델에서 각각 0.23477/0.06567, OHLC-only에서 0.23727/0.06756이다. 원천 기록 모델의 10구간 ECE는 각각 2.5%p/1.7%p다. 홈런은 드문 사건이므로 50% 기준 정확도(92.5%)만으로 성능을 평가하지 않는다.

상세 구간별 표본 수, Wilson 구간, log loss, 지표별 정확도, 날짜 단위 paired bootstrap은 `kbo-candle-prediction-backtest.json`에 있다. Wilson 구간은 표본 독립성을 가정한 참고값이다. 날짜 bootstrap도 동일 선수의 장기 상관을 모두 해결하지 않는다.

## 실행 및 운영 연결

아래 명령은 저장소 루트 기준이다. DB 접속에는 기존 `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` 환경변수를 사용한다.

```bash
python -m pip install -r crawler/requirements.txt

# 기본 동작은 읽기 전용. 외부 기록 API 호출 없음.
python crawler/predict_next_game.py --output predictions.json

# 최초 운영 적용 시 명시적으로 파생 테이블 생성 + 결과 저장
python crawler/predict_next_game.py --init-schema --write-db

# 이후 안전하게 재실행할 예측 배치
python crawler/predict_next_game.py --write-db
```

Lightsail에는 새 Python 모듈 4개와 갱신된 크롤러/requirements를 기존 크롤러 디렉터리에, PHP `get_data.php`/`predictions.php`를 기존 API 위치에 배치한다. 기존 PHP 일정 파일을 재사용하므로 별도 일정 파일은 필요 없다. 프런트는 기존 빌드·배포 절차를 사용한다.

기존 오전 2시 크롤러가 2026 정규시즌 경계 안에서 수집·리그 집계·revision 갱신을 끝내면 예측 배치를 자동 실행한다. 휴식일에도 갱신한다. 첫 실행 시 파생 테이블을 생성한다.

예측 기능을 활성화한 크롤러는 스케줄 요청 실패나 일부 경기 응답 누락, 한쪽 팀 박스스코어 누락이 확인되면 적재 전 중단한다. 이미 DB에 있는 과거 누락·중복·기록 정정 이력까지 판별하는 것은 아니다. 예측 재시도는 위의 예측 배치만 실행한다. 기존 크롤러의 단순 INSERT 수집을 무작정 재실행하지 않는다.

API는 모델 버전, source revision, 선수의 현재 정수 누적 기록과 마지막 기록 출전 날짜를 확인한다. 불일치면 확률을 숨기고 갱신 상태를 표시한다. 생성 후 48시간이 넘으면 지연 상태를 표시한다. 원천 직접 수정 후에는 기존 리그 집계/revision 갱신과 예측 배치를 함께 실행해야 한다.

## 재현 및 검증

```bash
python -m unittest discover -s crawler -p test_predictions.py -v
node --test frontend/src/pages/Kbocandle/chartData.test.js frontend/src/pages/Kbocandle/predictionData.test.js
php backend/tests/candle_predictions_test.php
cd frontend && npm run build
```

로컬 스냅샷은 Git에서 제외한 `.prediction-artifacts/records.json.gz`에 있다. 형식은 gzip JSON `{bounds: {year: [start,end]}, rows: [[PK,date,game_id,player_id,inning,pa_result], ...]}`이며 SQL의 시간순 정렬을 유지한다.

```bash
python crawler/predict_next_game.py --snapshot .prediction-artifacts/records-through-2026-09-19.json.gz --through 2026-09-19 --output .prediction-artifacts/predictions-through-2026-09-19.json
python crawler/backtest_predictions.py --snapshot .prediction-artifacts/records.json.gz --output .prediction-artifacts/backtest-v2.json --draws 2000 --every 5
```

`--every 1`은 표본 추출 없는 전체 평가다. `--reuse-samples`는 동일 모델 버전/데이터 해시/시뮬레이션 횟수/추출 간격의 캐시만 재사용한다. 생성 규칙을 바꾼 뒤에는 캐시를 재사용하지 않는다. 오프라인 스냅샷은 `--write-db`와 병용할 수 없다.

v2 검증 완료: Python 계산·시점·집계 테스트, JS 표시 조건/확률 합계 테스트, 프런트 빌드, 실제 계산값을 사용하는 로컬 카드 시각 확인. PHP 런타임은 이 로컬 환경에 없어 v2 변경 후 실행하지 못했다.

## 남은 한계

- 기존 DB의 소급 정정과 당시 수집 시각 이력이 없어 완전한 point-in-time 데이터 검증은 아니다.
- 동일 이닝 타석 순서는 기존 PK를 보조 정렬로 사용한다. 공식 이벤트 순서가 아니므로 OHLC High/Low 비교에 한계가 있다. 경기 합계에는 영향이 없다.
- 공식 박스스코어와의 전량 대조나 새 데이터 수집은 하지 않았다. 미분류 결과가 나오면 추론은 중단한다.
- 현재 일정표의 2026 정규시즌 끝은 12월 31일이다. 실제 종료일이 확정되어 기존 일정표를 갱신하면 예측 배치도 그 경계를 따른다.
- 평가 시점은 기록된 출전일이다. 휴식일마다 반복 발행된 예측은 별도로 중복 평가하지 않았다.
- 타석 없이 원천 행이 남은 출전은 반영한다. 수비만 하고 행이 전혀 없는 출전은 현재 DB에서 확인할 수 없다.
