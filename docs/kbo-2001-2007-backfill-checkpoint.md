# KBO 1군 2001–2007 백필 상태와 재개 정보

2026-10-01 공식 조회로 확인된 정규시즌 3,640경기를 운영 DB에 반영했다. 타자 291,855행, 투수 28,961행, 일정 3,640건이다. 최초 제외한 타석 결과 누락 7경기는 이후 사용자가 지정한 `아웃`을 적용해 반영했다. 공식 원문은 수정하지 않았으며 사용자 지정값이라는 근거를 별도로 보관한다. 시범·포스트시즌·올스타 공식 일정 조회 응답은 비어 있어 해당 범위가 완전하게 수집됐다고 확정하지 않는다. DB 런타임은 원래 16MB이고 운영 API는 정상이다.

## 사용자 결정

- 공식 문자중계가 없으므로 같은 이닝의 두 출루 타석 중 처음 타석에 주루사를 연결한다. 5경기를 단건 재검증해 통과했다.
- 공식 타석 결과가 비어 있는 7경기는 미해결로 남기고 확인된 경기부터 반영한다.
- 메모리 설정을 임시 128MB로 바꾸고, 반영 후 16MB로 원복하며 MariaDB를 각각 재시작하는 방식을 허용했다.
- 지정한 기존 관리자 비밀번호 파일의 사용은 허용했지만 인증이 실패했다. 그 방식으로는 설정을 바꾸지 않았다. 비밀번호는 출력하거나 저장소에 저장하지 않았다.
- 사용자는 처음에는 정상 종료 대기를 선택했지만, 이후 운영 복구를 우선하도록 지시하고 "걍 강제종료해"라고 명시적으로 승인했다. 승인 후 기존 PID와 실행 파일을 확인해 해당 프로세스만 종료했다.
- 최초에는 타석 누락 7경기 제외를 선택했지만, 이후 "그냥 타석 결과를 '아웃' 이라고 저장해놔"라고 명시적으로 지정했다. kbo_early_missing_pa_overrides.json에 7개 경기·선수·이닝·타순을 제한해 적용하고 source_corrections에 사용자 지정 근거를 남겼다.

## 복구 후 백업과 반영 코드 보완

2026-10-01 17:05 KST 현재 운영 DB의 50개 기본 테이블과 루틴·이벤트·트리거를 mariadb-dump로 백업했다. 서버 파일은 official-2001-2007/recovery-backups/operating-db-20261001T080504Z.sql.gz이며, 36,650,399 바이트, SHA256 148237aa12cf2864163f81f300c7c95bf2556c858a9f62e39da5f18872844329다. 전체 gzip 읽기·완료 표시·기본 테이블 정의 포함 여부를 확인했다. 로컬 TEMP/wesiper-recovery-backups에도 저장소 밖 사본을 내려받고 체크섬 일치를 확인했다. 복원 테스트는 아직 하지 않았다. InnoDB는 single-transaction 스냅샷이며, MyISAM 5개 테이블은 무중단 읽기여서 테이블 간 동일 시점 일관성을 보장하지 않는다.

backfill_kbo_early_official.py는 기본 1경기, 최대 5경기로 트랜잭션을 제한한다. 커밋 전에는 해당 배치 경기만 검사하고, 연도 전체 검사는 커밋 완료 후 1회 수행한다. write 실행 시 백업 상태와 SHA256을 확인하며 쓰기 세션 쿼리는 15초로 제한한다. 최초 1경기 실제 저장·검증·커밋 후 나머지를 이어갔다. 기본 1경기 실행에서 최대 5경기 실행으로 전환했고, 사용자 재승인으로 임시 128MB를 적용해 완료한 후 16MB로 원복했다. 중단 신호 처리는 진행 중 배치의 커밋·영수증 기록을 마친 후 멈추도록 개선했다. 중단 시 영수증에서 빠진 커밋 경기는 모든 타자·투수·일정 필드를 검증된 계획과 대조한 경우만 영수증을 복구하며 DB를 재작성하지 않는다.

- 연도별 실제 저장 행 수·경기 수·주루사 합계가 최신 캐시 계획과 일치했다. 원래 누락 7타석은 사용자 지정 `아웃`으로 보완했고, 해당 7경기를 추가 반영했다. 실제 아웃 7행의 팀·선수·이닝·타순·타석 인덱스·상대 투수를 DB에서 확인했다. 공식 원문상의 정확한 타격 결과를 복구했다는 의미는 아니다.
- 설정 파일 원본 바이트 일치, 런타임 16MB, event_scheduler=ON, 운영 todayGames.php/teamRank.php HTTP 200 및 JSON 오류 없음 확인.
- DB 임시 테이블을 생성하지 않았다. 일일 크롤러 코드는 이번 작업에서 변경하지 않았다. 주 백필·파서 코드의 로컬/운영 SHA256 일치를 확인했다.
- 실제 결과는 verified-summary.json, final-report.json, protected-after-all-current-rows.json과 각 연도의 write-receipt.json에 있다. 로컬에는 crawler/kbo_early_verified_summary.json을 보관했다.
